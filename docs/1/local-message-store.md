# birdman-store: the local SQLite cache

`crates/birdman-store` is the whole persistence layer, and the single source of
truth the UI renders from (see [[ui-sync-store-data-flow]]). One file:
`src/lib.rs`. Synchronous `rusqlite` with the `bundled` feature — no async, no
ORM, no query builder. Hand-written SQL throughout.

## Opening and connection setup

`Store::open(db_path, data_dir)` (and `open_in_memory` for tests) routes through
`Store::init`, which:

1. sets `journal_mode = WAL`
2. sets `foreign_keys = true` (the schema leans on `ON DELETE CASCADE`)
3. executes the `SCHEMA` batch of `CREATE TABLE IF NOT EXISTS`
4. runs `migrate` (see [[schema-migrations-without-a-framework]])
5. creates `<data_dir>/attachments/`

The `Store` holds one `Connection` and is shared as `Arc<Mutex<Store>>` between
the UI and the sync engine.

## Tables

`accounts`, `folders`, `messages`, `message_bodies`, `attachments`,
`message_threads`, and the FTS5 virtual table `messages_fts`.

Two structural decisions worth knowing before writing a query:

- **Envelopes and bodies are separate tables.** `messages` holds cheap header
  data; `message_bodies` holds the expensive `BODY[]` payload, written only once
  it's actually fetched (`body_fetched` flag on `messages`). See
  [[message-schema-and-lazy-bodies]].
- **Attachment bytes are not in SQLite.** They're content-addressed files under
  `<data_dir>/attachments/`, with only metadata plus `cached_path` in the
  `attachments` row. The database file stays small.

`message_threads` exists as shape only — JWZ-style threading was deferred, and
nothing populates it yet.

## Identity: `(folder_id, uid)` locally, `message_id_header` across folders

IMAP UIDs are unique only *within* a mailbox, which is why `messages` has
`UNIQUE(folder_id, uid)`. Cross-folder identity needs the RFC 5322
`Message-ID` header — a distinction that matters enormously on Gmail, where
labels are folders. See [[cross-folder-search-dedup]].

## Query conventions

- **Keyset pagination, never `OFFSET`**: `list_messages_page` uses
  `WHERE (date, id) < (?, ?)` with the `idx_messages_folder_date` index, so deep
  scrolling stays cheap. `PageCursor` is the opaque cursor type.
- **Shared row-mapping functions**: `folder_row` and `message_summary_row` are
  used by every query returning those shapes, and their doc comments list the
  exact column order each `SELECT` must produce. If you add a column to a
  `SELECT`, update the mapper and every caller together.
- **Newtype ids**: `AccountId`, `FolderId`, `MessageId`, `AttachmentId` are all
  generated by the `id_type!` macro. Pass those, not bare `i64`.

## Tests

Unit tests live inline in `#[cfg(test)] mod tests` at the bottom of `lib.rs`,
using `Store::open_in_memory` with a `tempfile::tempdir()` for the attachment
directory. They cover pagination gaps/dupes, body laziness, and the search
dedup behavior specifically. See [[testing-approach]].
